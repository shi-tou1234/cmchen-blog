怎么看待我的开源项目。GitHub 上目前 13 个仓库，分四类：博客与主页、学习与电子信息工具箱、桌面效率工具、AI agent 装备。下面逐个说清楚它们能干什么、怎么用、用的时候注意什么。

* * *

## 博客与主页

**cmchen-blog** 是一个功能比较完整的静态博客。基于 Astro 构建，文章用 Markdown 写，支持 Frontmatter 元数据、文章分类、标签系统、时间线归档页、阅读进度条、预计阅读时间、文章置顶、数学公式（KaTeX / Typst）、代码高亮（Shiki）、全文搜索（Pagefind）、深色模式跟随系统、响应式布局、AOS 滚动动画、粒子背景、页面切换过渡动画、自定义 Markdown 组件（音乐卡片、GitHub 卡片、引用块、提示框、推导过程浮层）、后台文章管理（在线创建编辑删除、站点设置、安全配置）、数据导出、文章实时预览与回填、PDF 转换、文件上传。还可以配置旅行地图城市标记和音乐播放列表。

用的时候，clone 仓库到本地，按 README 里的步骤填写站点地址和你的个人资料，推到 GitHub 开启 GitHub Pages 就能跑。后台地址是 `/admin/`，第一次进入时设置密码，之后写文章、改站点配置都在后台完成，不需要碰代码。

注意几个问题：预览图片的路径如果换成自己的仓库，需要把 README 和配置里的 `shi-tou1234/cmchen-blog` 替换成你的用户名和仓库名，否则图片会裂。后台写的文章自动保存到浏览器 localStorage，发布前建议本地先 preview 一遍确认格式没问题。站点默认不开放搜索引擎收录（noindex），如果你想被收录，需要改 SEO 配置。

**cmchen-blog-starter** 是上面的"抽真空版"。功能框架和工程配置全部保留，文章、关于页、个人资料、工具栏链接、旅行地图、音乐播放列表全部清空。你 clone 下来填自己的内容就能直接用。如果你觉得完整版太臃肿，这个更合适起步。配置方式跟完整版一样，改 `astro.config.mjs` 里的站点地址，推上去部署。

这两个仓库的区别就是：starter 是开箱即用的空壳，blog 是功能齐全的成品，也是 starter 的功能参考。

**cmchen-page** 是我的个人主页，React 19 + Vite 构建。最显眼的是背景：一段四百多行的原生 WebGL 片段着色器，噪声星云、三层视差星空、错峰流星全部由着色器实时画出来，没引 three.js，主包 gzip 只有 80 kB 左右。滚动动效参考了 eladiodieste.com 的做法：开场四阶段 Preloader、200svh 滚动跑道式 Hero、快滚时跑马字带倾斜、区块色温随滚动从奶油过渡到琥珀、Skills 榜的 odometer 数字滚动。

内容全部外置成 `src/data/content/` 下的 JSON，改文案不碰组件；`#/admin` 有可视化后台，表单填完直接通过 GitHub Contents API 提交到你的仓库，Actions 自动重新部署。

用的时候，clone 下来 `npm install` 后 `npm run dev`，Windows 双击 `start.bat` 一键启动。想改成自己的主页，把 JSON 里的资料换掉、背景着色器的配色调一下就行。

注意：后台密码是 PBKDF2 哈希存在 `public/admin-security.json` 里，忘了只能重新生成；富文本字段只解析 em/strong 这几个标签，塞原始 HTML 不会生效；如果你的网络环境有 TLS 拦截代理，构建时拉 GitHub 数据快照可能失败，脚本会保留上次有效值继续构建，不用管。

## 学习与电子信息工具箱

**cmchen-study-platform**（学习工具台）是四个工具合一的纯前端页面，卡西欧 fx-991 风格的深色 UI，零依赖、零网络请求。顶栏四栏目切换：科学计算器（标准、方程、矩阵、向量、统计、微积分、复数、进制、逻辑、表格、工具共 11 种运算模式）、布尔化简（真值表 → Quine-McCluskey → 最简表达式，最多 10 输入 10 输出，自动标注异或同或）、实验记录（按实验项目录入数据、拍照留证、导出 CSV）、数据处理（统计分析、图表绘制、线性/多项式拟合）。

这个仓库的前身是我最早分开写的 jisuan（计算器）和 zhenzhibiao（真值表化简），后来发现它们本来就是电路课一对搭档，就合并成了一个工具台，顺带补上了实验记录和数据统计——大物、模电实验报告需要的东西齐了。

直接浏览器打开 `index.html` 就能用，在线版挂在 GitHub Pages 上。栏目选择记在浏览器里，也支持 URL 深链接直达某一栏。

注意：角度制/弧度制切换会影响三角函数结果，算完记得切回来；布尔化简的变量名只允许字母和下划线开头，NOT 运算符用上划线写法，跟 `!A` 那种传统写法不一样；实验记录和数据处理的数据存本地浏览器，清缓存前先导出一份 CSV。

**links** 是一个浏览器端的网页链接导航，专门给电子信息学科用的。分了好几类：芯片选型（半导小芯、立创商城）、EDA 工具、竞赛资源、求职准备。每张卡片有图标、简介、标签，点进去直接跳转。支持关键词搜索（输入名称或标签实时过滤）、本地收藏（星标按钮，下次直接进收藏夹）、深色模式（跟随系统自动切换）、瀑布流布局、移动端适配。

直接浏览器打开 index.html 就能用，不需要装任何东西，不需要后端，不需要联网——除了第一次打开加载 CDN 资源。

注意：部分链接已经做了国内适配（半导小芯换成了 semiee.com，英飞凌换成了 infineon.cn，全国大学生机器人大赛换成了 cnrobocon.net），如果你的网络环境能直接访问国外站点，这些链接在 README 里有原始地址可以改回来。收藏夹数据存在浏览器 localStorage 里，换浏览器或清数据会丢，没有云端同步。

**box**（BENCH-01）是焊接元器件的库存管理工具。你在实验室拆了电阻电容、收了芯片，往里面录名称、型号、封装、数量、位置、数据手册链接，之后找东西的时候搜一下名称或型号就能出来。支持按分类（电阻、电容、MCU 等）筛选、按封装筛选、按库存状态（正常/低库存/缺货）筛选。统计页面显示总元件数、总库存数、低库存提醒、缺货计数。列表页和详情页双栏布局，点进去看具体参数和备注。

数据存在浏览器 localStorage 里，不上传到任何服务器。后台有 Gist 同步功能，配一下 GitHub Token 就能在不同设备之间同步。

注意：数据只存在当前浏览器，清浏览器数据或者换设备会丢，建议定期用 Gist 同步备份。后台密码只存在 localStorage 里，忘掉了需要手动清浏览器数据重置。数据手册链接字段支持 http/https/mailto 以外的链接会被过滤掉，不生成可点击的超链接。部分元件的 datasheet 只有 PDF，浏览器里点链接需要你的电脑装了 PDF 阅读器。

**yulan**（预览）是一个浏览器端的 Markdown 实时编辑器。左边写 Markdown，右边实时渲染出效果。支持的语法包括：标题、引用、列表、任务列表、表格、链接、图片、删除线、行内公式和块级公式（KaTeX）、代码高亮（Highlight.js 自动识别语言）、水平线。支持明亮/深色主题切换，跟随系统自动变化。编辑内容自动保存到浏览器 localStorage，关掉页面再打开不丢。写完一键导出 `.md` 文件。

直接浏览器打开 index.html 就能用，不需要任何依赖，不需要服务器。

注意：首次打开需要联网加载 CDN 资源（KaTeX、Highlight.js、DOMPurify），加载完之后即使断网也能正常编辑和预览。本地存储的内容只保存在当前浏览器，换浏览器会丢，导出之前建议先点一下下载按钮存一份。内容经过 DOMPurify 清理 HTML，安全性有保障，但如果你粘贴了带格式的富文本，可能会丢失部分样式。

**word**（单词助手）是一个英语单词学习工具。功能包括：录入单词（自动补全音标和释义，支持批量导入）、单词库浏览（卡片形式查看已收录的单词，带图片墙）、四种练习模式（英译汉四选一、汉译英拼写、选择题、填空题）、每日复习计划（根据你的错题率自动安排每天复习哪些词）、标准真人发音（Web Speech API）、深度词义解析（含中英双解、例句、固定搭配）、词库导出（导出为 Word 文档，方便打印）。

有两种运行方式：简单模式直接用浏览器打开 `词库管理.html`，完整模式需要解压 `server.zip` 双击 `启动单词助手.cmd` 启动本地服务。完整模式支持更完整的多设备数据同步体验，服务端用 Node.js 编写。

注意：简单模式下数据存在浏览器 localStorage，换浏览器会丢。词库导入的文件格式需要跟系统导出的格式一致，导入前建议先备份现有词库。Web Speech API 的发音质量取决于你电脑上安装的语音包，部分单词可能读不准。导出 Word 文档需要浏览器支持 Blob 下载，老版本 IE 不行。

**card**（老年人应急信息卡）是这份列表里最早的仓库，一个微信小程序。把老人的基本信息、过敏史、慢性病、服用药物、住址、紧急联系人编码成一张专属二维码，老人走失或突发不适时，好心人或医护微信扫码就能看到结构化的应急视图，过敏史这类保命信息红色加粗，还能一键拨打紧急联系人或 120/110/119。二维码在手机上本地生成，可以存相册、打印成实体挂件。

用的时候，装微信开发者工具，clone 仓库后导入项目根目录、填 AppID 编译预览，走公众平台审核就能发布。

注意：所有数据只存在手机本地 `wx.setStorageSync`，不上传任何服务器，生成二维码全程离线——这是设计底线，别指望云端找回，手机丢了数据就没了，所以做好物理打印备份。二维码生成引擎是纯 JS 实现的（`utils/qrcode.js`），没有第三方依赖，但也意味着数据量大时编码密度会变高，信息尽量精简。

## 桌面效率工具

**cmchen-desktopbox**（DeskBasket）是一个 Windows 桌面整理程序：把桌面上散落的文件、文件夹、快捷方式收进几个"文件夹筐"分类摆好，屏幕底部再放一条常用软件 Dock。核心原则是它不动你的文件——筐只登记绝对路径，绝不移动、删除、改名，桌面上的图标原样待在原地，筐只是一层分类视图加启动面板。Dock 支持常驻或自动收起（碰一下屏幕底边滑出来），图标悬停按余弦衰减依次放大，弹窗里双击文件夹继续钻、拖文件进去边框会亮一圈。外观支持完全透明和 Win11 磨砂玻璃两种材质，配色自动跟随壁纸亮度，多显示器下 Dock 可跟随鼠标所在屏。

用的时候，`npm install` 后 `npm start`，程序直接进托盘，所有入口在托盘右键菜单和屏幕底部的 Dock；`npm run dist` 打包成免安装 exe。

注意：它是 Windows 专属实现（注册表自启、WinRT 图标提取），macOS/Linux 跑不了。Dock 只在桌面层显示、不压窗口，切到别的应用就看不见了，这是特性不是 bug。设置文件每次保存前留 `.bak` 备份，损坏自动恢复；后台"改名"只改显示名，磁盘文件名一个字都不动。

**cmchen-clock**（DesktopClock）是一个跨平台桌面时钟，Python + PySide6 写的。像壁纸一样贴在桌面上、被打开的窗口自动遮挡，也可以置顶或当普通窗口用。字体可以从系统字体下拉选、也可以加载 ttf/otf/ttc 文件，字号 8–200、任意颜色、不透明度 10%–100% 全可调，设置面板里实时预览。屏幕位置九宫格一键摆放，也能输精确坐标；托盘常驻，左键单击隐藏/唤回；每秒整点对齐刷新，几乎不占 CPU。

双击打包好的 exe 就能跑，或者 `python main.py`；开机自启在菜单里勾一下就行。

注意：运行时依赖只有 PySide6-Essentials 一个包，但打包后的单文件 exe 约 36 MB，别嫌大，Qt 就这个价。Linux 下 Wayland 会话里"固定在桌面"受系统限制，会自动降级成普通窗口行为，想要桌面模式得用 X11。

**cmchen-translate**（划译）是跨平台划词翻译：在任意软件里选中文字按一下 `Alt+Z`（macOS 是 `Cmd+Z`），光标旁弹出小窗显示译文；`Alt+S` 框选屏幕任意区域走 OCR 识别图中文字再翻译。翻译引擎用的是你自己的 OpenCode 网关免费模型，不用为翻译另外注册付费，模型挂了（429/503/超时）自动降级备用模型重试。OCR 在 Windows 上用系统自带的 WinRT（离线、中英都支持），macOS/Linux 用随包的 Tesseract WASM，运行时也是离线的。

前往仓库的 GitHub Releases 下载安装包：Windows 有安装版和单文件便携版，macOS 有 arm64 的 dmg，Linux 有 AppImage 和 deb。

注意：macOS 首次打开会提示"未知开发者"，右键选打开；Windows SmartScreen 提示时点"仍要运行"；Linux 的 AppImage 要先 `chmod +x`。macOS 需要授权辅助功能权限，不然全局快捷键钩子收不到。另外项目自带 84 个单元测试，打 tag 推上去 GitHub Actions 会自动构建三平台产物传 Release，想改源码重打包的可以放心动手。

## AI agent 装备

**cmchen-skill** 是我的 AI agent 技能包合集，基于 Claude Code 的 Skill 机制构建，现在有九个技能包：

* **cmchen-writing**：写文章的时候开。基于博客 84 篇、约 111 万字全量语料重建的风格系统，六种模式（冷白描、热日记、锐评、沉浸、笔记、追问），每条规则有原文背书，中途可以逐模式切换。它写出来的不是通用好文章，是"像 cmchen 写的"文章；素材不足时它会直接说写不了，不硬凑——这是我设的死线。
* **cmchen-learning**：学专业课的时候开。回合制教学，讲得懂、记得住、能做题，预习框架、知识点笔记、结课总结自动落盘。
* **cmchen-practice**：出练习卷的时候开。材料批量出四类题型，错题本、变式专练、期末冲刺包，错题本跟 learning 共享。
* **cmchen-blog-writing**：有 PDF/PPT/讲义要转博客文章的时候开。读文件、提取结构、输出带 Frontmatter 的 Markdown，公式走 KaTeX，容器指令有机械校验。纯图片扫描件只输出结构化笔记，不硬配导语和总结。
* **cmchen-self-evolving-agent**：需要 agent 记住跨会话的信息时开。记忆体系 + 反思机制 + 控制指令。
* **cmchen-security-scan**：审代码的时候开。本地只读扫描，不依赖云端，产出报告直接看。
* **cmchen-agent-thinking-guidance**：让任意 agent 模仿 Claude 的思考过程与工具调用行为规范。一个遵守流程的中等模型，胜过自由发挥的强模型——质量在结构、证据与诚实，不在模型本身。
* **cmchen-political-writing**：高校政治类论文写作，五类型路由，活人感基调。
* **cmchen-session-wrapup**：会话收尾三步流：清垃圾 → 同步 README → 确认后提交推送。写长Session的最后一段路就交给它。

用的时候，把 `cmchen-skill` 仓库 clone 下来，里面每个技能都是一个独立的文件夹，复制到 Claude Code 的 `skills` 目录下，重启 Claude Code 就能在技能列表里看到。仓库里另有一个 `dsh适配/` 打包工程，把这些技能适配成 DeepSeek Harness 可安装的 bundle。

注意：这些技能包是为 Claude Code 设计的，其他 agent 框架（比如 Cursor、Windsurf、Continue）不一定能用。每个技能的 README 里有详细的触发词和用法说明，用之前建议扫一眼。cmchen-writing 和 cmchen-security-scan 有配套的自动质检脚本，长稿建议跑一遍检查硬禁令。

* * *

这些项目之间是能咬合的：links 查到芯片、box 记库存；study-platform 一个页面顶了过去计算器、真值表两个仓库，配 desktopbox 把课件和数据分筐摆好；翻译交给划译，时间显示在桌角；写下来的东西经 blog-writing 转成文章，由 writing 定语气，最后进 blog 发布。从 starter 到主页到技能包，是我从学习到输出的完整一条流水线。

你可以按需取用，也可以全部拉下来跑一遍，看看我平时在折腾什么。

谢谢你看到这里，祝各位开发者好运。
