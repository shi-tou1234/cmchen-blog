上一回写到7月3号，我在结尾说：这个项目可能永远不会做完。

现在一个多月过去了。它确实没做完，但这次我干了一件以前从来没干过的事——我把它开源了。

从一个叫"-"的仓库，变成一个叫 cmchen-blog 的仓库，再变成一套能给别人用的初始化模板。一个多月，110次提交。

事情是这样的。

* * *

其实7月4号到25号，又提交了26次。不多，但全挤在两天——7月9号12次，7月10号8次。那两天干的活，放到现在看都算得上大活。

先说7月9号。那天我把一份分了三档的问题清单，从头到尾修了一遍。清单叫 P0/P1/P2：P0 是出人命的那种，P1 次要，P2 是看着碍眼的冗余。

P0 里的头号问题，是登录。原来的代码里有个 DEFAULT_SECURITY 硬编码密码回退——安全配置加载失败的时候，自动落到一套写死的默认密码上。这套东西的逻辑是"配置坏了你还能进去"，但它同时意味着：谁拿到源码，谁就拿到了那个默认密码。删。加载失败？那就禁用登录，宁可进不去，不能裸奔。

同一天还动了 GitHub Token，从 localStorage 挪到 sessionStorage——关掉标签页就清空，降低被偷的风险。

对，那段时间我补了一堆以前从来没听过的安全名词：XSS、Open Redirect、PBKDF2。PBKDF2 是密码哈希算法，迭代次数从 18 万提到 60 万，据说是 OWASP 标准。你只需要知道一件事：同一个密码，以前验证要算 18 万次，现在要算 60 万次，暴力破解的成本翻了三倍多。

后来我又觉得 sessionStorage 太狠了——关个标签页就掉线，天天重新登录，烦。于是加了个「记住 Token」复选框：不勾选就存 sessionStorage（关标签即清，安全优先），勾选了存 localStorage（长期保留，便利优先），切换时自动迁移，不留残渣。

先为了安全把它从永久的挪到临时的，又为了方便给它加了个永久开关。安全与便利打架，打到最后 AI 给的方案是：都给你，你自己选。

7月9号下午还折腾了一件小事：归档页那个 hover 动画。四次提交，commit message 分别是：修复死板、修复卡顿（缩短时长并移除 reflow）、恢复原始摘要动画、用 grid-template-rows 替代 max-height 修复机械感。

一天之内，从死板到卡顿到机械感再到修好，一个动画改了四版。

（我盯着那四次改动看了半天，愣是没看出太大区别。但 AI 说好，那就是好。）

然后是7月10号。重头戏，公式推导浮层。

就是文章里那些公式，鼠标悬停上去（移动端是点击），弹出来这个公式的完整推导过程。

这个功能我一直想要。我的笔记全是数学物理公式，看一个定理只知道结论，不知道它怎么来的。期末复习的时候，最恨的就是"这个结论哪来的"。现在 hover 一下就能看到。

功能本身一天做完：一个 rehype 插件，一个浮层组件，顺带把后台重写成三栏分屏——列表、编辑器、预览，一屏看全。

真正麻烦的是给内容补推导。48篇笔记，数学的微积分、级数、复变函数，物理的静电场、磁场、电磁感应、力学、刚体，电路的相量、三相、动态电路，数字电路的逻辑代数、触发器——一篇一篇找关键定理，补推导过程。一共650个推导容器。

650个。这活要是纯手写，我现在还在写。是让 AI 一篇一篇扫，扫完自己生成推导，我负责抽查。

同一天，性能优化加工程化。移除反爬虫——就是第一篇里那个"禁用右键和 DevTools"的骚操作，我当时还吐槽"你觉得能防住谁"，这次总算连根拔了。还有字体预加载、粒子降负、死依赖清理。然后上工程化三件套：ESLint、Prettier、CI check，外加 Lighthouse CI 做性能审计。

还有那个后台预览框，前后修了三次。预览 iframe 没法滚动。第一次修"embed 模式无法滚动 + 源码/预览切换失效"，第二次发现是 iframe 没确定高度，内部才滚不动，第三次用 position:absolute 把 iframe 包起来，把高度钉死。7月10号两次，7月11号又补了一次。

修一个"预览滚不动"，用了三天。

7月11号和24号没什么好说的，《ai工具》《专业软件篇》各更新了一版。接下来是7月25号。

7月25号那天我在写《第一次参加智能车》，一口气传了11张图片。第二天开始折腾字体——换了一套新的字体方案，顺便修了一个之前一直没注意的bug：原来的字体大小设置，是把整个页面的所有元素一起缩放的，不只是正文。你调大一号字，标题、导航、按钮全都跟着胖一圈，整个页面像被拉过皮。这次改成只影响正文。7月27号又顺手把 markdown 正文的行高调大了一点，说是提升可读性。

再然后，7月29号，我把浅色主题从默认的白改成了护眼暖黄色。

这个改动我说不上来为什么，就是看白看腻了。暖黄的底配暖黄的字，评论框和后台预览也一起换了色。看着确实舒服一点，但说实话，我有点怀疑这是不是我的心理作用。

哦对了，7月31号我干了一件跟代码完全无关的事——写了一篇《我的b站宝藏up主推荐》。21张截图，23次提交，全是传图。

（写文章传图都能传掉一天，这就是我的水平。）

* * *

然后就是8月2号。这一天，我愿称之为我的重构纪念日。

17次提交，从下午2点干到晚上6点。

先从修bug开始。第一批6个功能性bug：

* 后台工具栏里那个"图片"按钮，点了半天发现根本没有功能，删了
* 新手指南弹窗，之前有两套开关，合并成一套，删掉多余的组件
* 登录按钮等安全配置加载完再启用，不然你手快一点，它就给你报"密码错误"
* 修改密码失败的时候补了个错误提示（之前失败了，你都不知道为什么失败）
* 搜索关键词高亮，原来的底色是透明的，亮了个寂寞，改成不透明黄
* 修复阅读模式去底部留白

第二批6项，4个bug加2个安全项：

* 公式推导浮层，鼠标一移开就消失，还清理了换页时累积下来的全局监听
* 文章目录重复初始化
* 后台预览回填，原来自动覆盖你的改动，改成手动"从预览回填"
* 封面缺图的时候自动用封面API兜底，不再显示一个破图
* 上传文件名和导出路径统一做安全字符清洗，防目录穿越
* 发布时对标题、简介做转义，防文件头注入

第五和第六条，是让一个学硬件的第一次去处理安全问题。我第一次听说目录穿越这种东西——就是你传一个文件名，比如 `../../../etc/passwd`，它可能顺着路径往上爬，爬出你的文件夹。AI告诉我这是漏洞的时候，我才知道上传文件原来还有这种玩法。

bug修完了，然后开始动刀子——阶段1清理。

这次清理比以前任何一次都狠。删掉了一整套 Svelte。对，整套。Svelte 是什么时候被我塞进项目的，我已经不记得了，大概是某个功能要用到的组件框架，用完就一直躺在那里，集成、依赖、配置、页脚图标、prettier 插件，全套。

还有 typst.ts 里没用的依赖、friend.ts、6处"排除 welcome 文章"的无用过滤、失效的 RSS 兜底函数、后台那个旧的"插入片段"下拉框、过时的上游文档。能删的都删了。

然后是合并重复代码。文本清洗、哈希算法、回到顶部按钮、滚动进度计算、链接下划线样式、frontmatter 解析，全部抽成公共函数。

阶段2是多语言拆壳。之前博客是带 `[...locale]` 路由的中英双语，这次把6个页面移出 locale 目录，路由不再带语言段。主题逻辑也收敛了——之前亮色是靠"删除 data-theme 属性"来切的，这次统一成 `data-theme="light"`。

阶段3是颜色统一。第一波把散落在各处的颜色收敛进 CSS 变量，第二波把暗色覆盖集中到变量。最后一天我还干了一件特别无聊的事——给变量改名。

`--button-hover-color` 改成 `--hover-bg-color`，因为那个变量实际用在卡片、代码块、芯片上，不只是按钮。`--button-border-color` 和 `--border-color` 的值完全一样，合并成一个。`--postcard-bg-color` 改成 `--card-bg-color`。

39个文件。只改名字，一个值都不动。

你问我这事有什么好写的？因为这种活 AI 干起来毫无怨言，而我盯着那39个文件的 diff，第一次体会到什么叫代码洁癖。

* * *

8月3号，阶段4。

* 弹窗统一：加了一个公共 modal 工具，锁滚动+Esc关闭+焦点圈住，移动菜单、指南弹窗、图片灯箱、搜索框，四个弹窗的行为终于一致
* 可访问性四项：恢复被抹掉的键盘焦点框、修暗色下的对比度、底部导航加 aria-current、页脚提示支持键盘聚焦
* SEO：保持全站 noindex（私人博客，不开放收录），文章简介接入 meta description，404从随机4篇改成最新4篇
* 移除CI假检查

最后这个我要单独说。之前我的 CI 里，类型检查和代码规范检查，都是 `continue-on-error`——检查失败了也照样部署，根本不拦你。

检查了，但检查失败也无所谓。这不叫检查，这叫假装在把关。

我盯着那个配置看了很久，把它删了。部署流程只保留安装、构建、上传。

* * *

8月4号，继续修一个我自己制造的bug。

那天加了"图片上传插入光标处"的功能，上传的图片插到正文光标位置，预览也即时刷新。结果一构建，直接失败——报错：`insertAtCursor` 重复声明。

同一个文件里本来就有个同名工具函数，是工具栏插片段用的。我新写的这个跟它撞了。AI 写代码的时候不会去翻你文件里有没有同名函数，它只管自己那一亩三分地。于是把新的那个改名成 `insertSnippetAtCaret`。

然后又发现一个问题：预览框里的图片，裂了。

raw.githubusercontent.com 在国内经常被墙，我引用资源走的 raw 链接，预览的时候图全裂。改成用项目里本来就用的 jsDelivr CDN 重写路径。改完连旧文章里那182处 `./assets/` 引用，在预览里也能正常显示了。

182处。我现在看到这个数字还后怕，这坑要是晚发现几天，我得手动改到什么时候。

* * *

然后是重头戏。

开源。

先说个背景。我这个仓库，在 GitHub 上的名字，之前一直叫一个横杠。就一个"-"。

对，减号。

我也不知道当初怎么就起了这么个名字，建仓库的时候估计随手敲的。这个"-"就跟了我快半年。你去翻我的合并提交记录，里面写的都是 `shi-tou1234/-`。一个减号，就是我博客这半年的家。

8月2号下午，重构收尾之后，我开始做开源前的准备——写 README。

原来的 README 基本等于没有，就几行字。那天让 AI 写了一版完整的：项目概述、功能特性、技术栈、目录结构、安装指南、使用说明、配置说明、自定义组件示例、部署说明，全给补上了。

然后折腾 LICENSE。先删了一个，再加了一个。

第一个 LICENSE 是从 Momo 主题那边克隆的时候一起带过来的，版权行还写着 `Copyright (c) 2025 Motues`。你开源自己项目的时候，总不能顶着别人的版权声明。删。换成 `Copyright (c) 2026 cmchen` 的 MIT License。

这一个删一个加，中间隔了5分钟。改 README 那几笔提交全是英文的，一看就不是我敲的。

然后8月9号，我干了件更决绝的事：把仓库名从"-"改成 cmchen-blog，顺便把部署路径的 base 从 /-/ 改成 /cmchen-blog/。

改名比想象中麻烦。代码里到处都是 `shi-tou1234/-` 的引用：astro.config 的 base、config.ts 里的 indexPage、关于页的音乐文件 URL、还有 git remote 本身，全得替换。改完推上去，线上样式直接404白屏——因为 base 还指向旧的路径，CSS 和 JS 资源全找不到。又修了一版才算稳。

但最重磅的是这个：我开源了一个初始化版本的仓库。

叫 cmchen-blog-starter。

它是这个仓库的初始化版本，把所有的个人内容删干净了——文章、关于、工具栏链接、旅行地图城市标记、音乐播放器，全删。只留下完整的功能和工程配置。别人克隆下来，填上自己的内容，改一下部署地址，就能得到一个功能齐全的博客。

我不知道你们能不能 get 到这件事的分量。

这个博客，从2月16号开始，123天做了932次提交，到今天1134次。从零开始，一行代码都没自己写过，全部是 AI 写的。半年过去，它变成了一套能给别人用的模板。

我当时的想法其实挺朴素的：这博客全是 AI 帮我写的，删掉我的内容它就是一套现成的模板，扔在那里也是扔着，不如整理一下，让有需要的人拿去。说不定有人跟我一样，想用 AI 搭个博客又不知道从哪开始，那这个 starter 就是他的起点。

而且你想想，一个没有编程基础的大一学生，用 AI 搭出来的东西，最后能开源出来给别人用。这事放在一年前，我自己都不信。

写完 README 里 starter 那段介绍，我又顺手给后台补了两个编辑器：站点信息编辑器（标题、标语、创建时间，抽成单一的 site-info.ts 数据源）和首页签名编辑器（首页那行打字机签名，可以后台改了）。

开源前把后台补全，大概是一种仪式感。

* * *

上回我说，这个项目可能永远不会做完。现在一个多月过去了，它确实没做完——我甚至还在往里面加功能，比如那两个后台编辑器。

但这次我想通了另一件事。

以前我觉得，一个项目要"做完"才算有价值。现在我觉得，一个东西能不能从你的手里走到别人手里，才是另一回事。

我的博客从"-"变成了 cmchen-blog，从个人仓库变成了别人的起点。它还是没做完，但它的生命，好像比"做完"更长了。

这次就先写到这儿吧。

下次再写《网站开发记录》，可能是哪天我又把它折腾散架了，也可能是我发现有人真的在用 cmchen-blog-starter 搭博客的那天。

谁知道呢。

反正代码不会自己跑，bug不会自己好。

而我，大概率明天还会让 AI 帮我改代码。
