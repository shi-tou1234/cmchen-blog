# DSH 装修折腾记录

> 8 月 14 号晚上在 GitHub 刷到 DeepSeek Harness，到 8 月 17 号——三天，从一个官方默认版的 DSH，折腾成了有桌面应用、有视觉模型、有移动端遥控、有自定义模式、有自进化记忆的个人 AI 工具链。129 条对话记录，19 个会话，4.5MB 的最大单会话，10 个提交，5 次构建失败，4 次手机白屏。
> 
> 这是一份带时间戳的折腾复盘。所有命令、报错、对话原文，都来自 DSH 自己的会话记录。

事情是这样的。

## 第一天（8.14 晚 ~ 8.15）：从零到能用

### 装起来

8 月 14 号晚上刷 GitHub，刷到 DeepSeek Harness——DeepSeek 官方开源的 agent 框架。万物皆插件的架构，Cordis 驱动，能接 DeepSeek 的模型，带一个 Web 界面。

我当时的想法很简单：这东西能当我的日常 AI 助手用吗？

克隆仓库、`pnpm install`、`pnpm run build`、`pnpm dsh web`。四步，官方文档写得很清楚。

然后就卡住了。`@anthropic-ai/claude-agent-sdk` 的 win32-x64 包下载超时。`pnpm dsh web` 在依赖检查那一步永远转圈。翻了大半天文档，在 `pnpm-workspace.yaml` 里加了一行：

    verifyDepsBeforeRun: false

跳过检查，终于启动了。就一行配置。

第一次看到 Web 界面的时候——很朴素。官方 UI 就是个能聊天的网页，没主题、没装饰、没记忆管理，连归档的恢复入口都没有（这个后面再骂）。但我知道这东西的潜力在插件。

### ModLens：让模型看见图片

第一件事，装视觉模型。官方的模型读不了图片，得靠 ModLens 让模型理解粘贴进聊天的图片。

    帮我安装 https://github.com/liustack/modlens

装完之后配 API。第一次填的 key 不对——请求地址写成了 `https://opencode.ai/zen/go`，少了 `/v1`。就一个 `/v1`，识图一直报错。

    换一个api:sk-2QWugo...,向mimo-v2.5，发请求 https://opencode.ai/zen/go/v1/chat/completions

换完 key，加上 `/v1`，还是不行。`这个识图没法用啊`。排查了半天——模型选对了没？`你告诉我我现在接入的识图模型是什么`。查到底，是引擎配置的问题：`~/.modlens/config.json` 里指向了 OpenCode Go 的端点，视觉模型是 mimo-v2.5。改对之后终于能看图了。`测试一下，你可以看见吗`——模型回了一张图的描述。

调通还没高兴多久，Claude agent SDK 又出问题了。`你是不是给我加了一个claude agent的包在我启动dsh的时候，我现在差点打不开dsh`。

这段特别有意思。同一个问题，我在对话里问了两遍，第一遍没解决。折腾半天才发现，是它在装视觉模型的过程中，偷偷给自己加了一个依赖——`@anthropic-ai/claude-agent-sdk`。装个插件，装出个意外惊喜。

（后来我知道了这个包是个惯犯。它最后一天被我亲手拉黑，那是后话。）

### Aqua 主题：毛玻璃好看，但有 bug

    帮我安装 https://github.com/WYH66666666/DSH-Transparent-UI-Plugin

装完发现问题：

`这个ui好像除了问题，只有侧边栏会有，对话这里没有啊？而且如果我设置好壁纸，关闭后再次打开就直接恢复默认了，我设置好的全部消失了`

毛玻璃主题只有侧边栏生效，对话区域一片实色。壁纸设置不保存，关掉再开回到默认——设置了个寂寞。

问题出在上游。最新版 v1.0.8 反而有兼容问题，固定用 v1.0.3 解决了。（对，一个主题插件，最新版不能用，老版本能用。你猜怎么着，这种事这三天里不止一次。）

安装方式也换了：源码方式安装，junction 链入 profile，改样式不用走发布流程，改完直接生效。

毛玻璃上桌了，又发现自己还缺一块——桌面版的高级模式里，会话区、详情区、标题区都不透明，玻璃背景透不出来。于是自己写了一个 `ui-aqua-desktop`（v1.0.0），桌面桥接包，把这三块也补成透明。

自己给别人的插件写插件，就为了让玻璃完整透出来。

### 归档管理：补上官方缺失的功能

`增加一个插件，可以管理已经归档的对话，支持恢复和删除`

官方只能把会话归档进「Archived」分组，没有任何入口查看、恢复、删除。你归档了就归档了，找不回来。归档做成单向的，跟删了没区别。

我花了大概两个小时，把这条链路补完了：RPC 接口 → 后端持久化 → 前端 UI。

`workspace.unarchiveSession` 和 `workspace.deleteSession` 两个 RPC 接口，`ui-session-archive` 完整的前端插件包——弹窗、两步确认、运行中会话拒绝删除。

但第一次测试删除的时候翻车了——报了一长串 `invalid_union` 错误。`我已经重启了，告诉我怎么操作可以删除归档页面`。`我没有看见归档箱按钮`。

修了两处才搞定。一个在后端参数校验，一个在前端按钮渲染。两个都是"看着没问题，跑起来就炸"的类型。

### 桌面应用移植：最难的一块

`将这个仓库中的dsh桌面端功能移植过来，并且不影响现在已经有的功能`

来源是 anywhere-labs/deepseek-harness-desktop 的 `dsh-plugin-desktop` 包。一个 Electron 壳，能把 dsh 从浏览器里拽出来变成原生桌面应用。

第一次尝试，直接下载 exe 打开——`但是昨天发生了一个问题就是我下载这个仓库提供的exe后在桌面上打开会影响我现在存在的玻璃主题和归档删除功能`。

发布版 exe 用的是独立的构建产物，跟我本地这套定制完全是两套世界。打开它，等于打开了一个没有玻璃主题、没有归档管理的"官方纯净版"。

解决方案：克隆源码，把所有 `@deepseek-ai/*` 依赖从发布版改为 `workspace:*`——和 `dsh web` 用同一份源码与构建产物。

开始构建。第一次失败。修了依赖，重新构建——又失败。

再试。再试。再试。

对话记录里有五条连续的`继续`。每一条都是构建失败后的重试。你能在记录里看到那个循环：报错 → 修 → 继续 → 报错 → 修 → 继续。五条"继续"，五次失败，从白天磨到晚上。

`不能像仓库一样，装在我的软件列表中用快捷方式打开吗？`

终于跑起来了。默认 profile 从 `desktop` 改为 `web`——这样桌面版直接继承 web 里的全部定制。玻璃主题、归档管理、ModLens、dsh-pocket，什么都不丢。

构建从 yarn 适配为 pnpm。根 `package.json` 新增了三个脚本：`desktop`、`desktop:build`、`desktop:dev`。`allowBuilds` 增加了 `electron: true`。

那天晚上做了第一次反思——`/cmchen-self-evolving-agent 开始反思`。把踩过的坑全部记进了记忆目录。

（当时还不知道，这个反思习惯后面两天还会再触发四次。）

## 第二天（8.16）：插件、遥控、搜索、技能包，全部塞进去

`提交至git,重写readme，详细介绍和云端仓库相比，增加了什么，自己优化了什么。https://github.com/shi-tou1234/cmchen-dsh`

第一次提交，README 写成了"和上游对比"的工程分析。然后被自己推翻了——

`不要拉取上游官方的，就管我自己用的就行了啊，我自己加了很多和官方默认版本不同的插件和功能，主要是讲解这个`

改了。又改了——

`还有视觉模型，移动端遥控，go额度监测，tabbit-browser，内置自己cmchen-skill`

再改——

`有些插件不是直接安装的，我自己进行过优化，如dsh-pocket移动遥控，ModLens视觉模型，Aqua玻璃拟态主题，用的也不一定是最新版本的`

README 重写了三次。三次啊朋友们，一篇 README。从"和上游对比"到"我这个版本多了什么"，从"插件列表"到"我自己做了哪些优化"。每重写一次，都更清楚自己想要什么——不想要一份工程报告，想要一份"这是我的"的说明书。

提交完一看远端仓库的数字，吓人——12000+ 个上游历史提交。我的东西埋在 12000 条提交底下，谁看得见？`做一次历史重写`。

用 `git checkout --orphan` 创建新分支，以第一个提交为根，cherry-pick 所有自研提交，把上游历史全部剥离。最后 force push。现在 GitHub 上只显示我的 10 个提交。

过程中踩了一个坑：建根提交时 `apps/desktop/.gitignore` 不在工作区，`git add -A` 把 `dist/`（400MB 构建产物）和两个 i18n sidecar 也收进去了。400MB 的构建产物差点被收进根提交。用 `git read-tree` 精确装载树解决了。折腾了两轮。

### dsh-pocket：手机遥控，折腾最久的插件

`我安装了这个dsh-pocket v1.3.2，但是手机扫码打不开，用不了`

手机扫码——白屏。`手机提示fail to load plugins`。

排查发现：dsh-pocket 的代理没有给 HTML 请求带上 `dsh-desktop-mode` 参数。`dsh-plugin-desktop` 的客户端插件要求 URL 带这个参数，否则 `apply()` 直接抛错。桌面 Electron 窗口由宿主注入这些参数，手机通过代理访问时却没有。

原理不复杂：宿主往 URL 里塞参数，代理转发手机请求时把参数丢了。补法是改 `lib/proxy.mjs`——对 HTML 文档请求 302 重定向到带参数的同路径 URL，让浏览器带着参数重新请求一次。

`可以扫码进去了，但是无法切换对话，无法查看到电脑上的对话记录，无法输入，而且界面ui有点混乱`

能进去了，界面乱了。界面乱了还不算完——玻璃主题在手机上没法用。

`解决一个问题就是电脑上的显示放在手机上就会很混乱，尤其是这个玻璃ui，透明的导致很多字重叠在一起了，并且按钮和按钮也有重叠的问题`

半透明背景让文字和按钮全叠在一起。桌面端不走代理不受影响，手机上是灾难。又改了 `proxy.mjs`，注入一段脚本：窄屏（≤1023px）且用户未显式设置时，自动关掉 Aqua。

公网隧道也折腾了一阵。`下面解决公网问题：报错提示下载cloudflared-windows-amd64.exe 放到...目录，我已经下载好放置了，还是提示这个`。

作者更新了 v1.3.2→v1.4.7，`今天早上起来作者发布更新了，然后我更新完，又进不去了`。

`不是，我的意思是我扫码以后进去一片白，无法加载出dsh`。`浏览器加载不出来这个网页`。`我扫码在手机浏览器的链接就是这个http://192.168.3.189:3081，但是它一直加载不出来`

更新后 proxy.mjs 的本地改动被覆盖了——重新改了一遍才搞定。

四轮白屏，四次排查，同一个文件被覆盖了两次。这个插件我改的代码不多，每一行都改得刻骨铭心。

### 搜索：试了三个方案

`dsh官方的网络搜索必须得用deepseek的官方api，导致现在不能search，有什么替代方法吗`

官方搜索需要 DeepSeek API Key——我没有。

第一个方案：`open.bochaai.com需要收费的`。第二个方案：Bing 免费但需要 Key。第三个方案：`dsh-web-search-bing`——不需要任何 Key，开箱即用。

`测试一下，告诉我明天杭州的天气`——第一次测试。`我重启了，再次测试，告诉明天宁波天气`——重启后测试。`现在联网搜索联网可以了，但是返回不了相关的内容，全是一些一般的东西`——搜索能用了，结果质量差。`为什么回复这么慢`——响应速度也成问题。

`重启了，测试一下吧，宁波今天天气`——再次重启。`我重启了，测试`——又一次。`再次测试`——第四次。

折腾了四轮才搞定搜索。最终方案是 Bing 后端 + `web_fetch` 工具重新启用。结果质量一般，够用——对一个没 key 的穷学生来说，免费能用就是胜利。

（哦对了，后来装 tabbit-browser 的时候，这个问题基本被根治了，那个用真实浏览器搜。）

## 第三天（8.17）：学习模式、性能对比、清理战场

### 学习模式设计

`我要基于F:\学习资料和D:\项目\博客站点\src\content\blog，打造一个学习模式，深度结合cmchen-learning，同时学习cmchen-self-evolving-agent中的用户画像的想法，不断完善我个人，这个模式下，主要是用来我的学习一些新东西和期末复习，你有什么想法吗，可以向我提问`

和 agent 讨论了学习模式的设计——新学习、期末复习、考前冲刺三种场景。新学习要的是"从零开始的路线"，期末复习要的是"查漏补缺的地图"，考前冲刺要的是"高频考点清单"。以博客笔记为知识库、学习资料为素材源，自动追踪学习状态和薄弱点。本质上就是把"我是谁、我学过什么、我哪里不会"打包成一个模式。

`/cmchen-learning 我要学习c语言中的数据结构的相关内容`——用学习模式测试了一下，能用。`输出结果：x=5,*ptr=10`——C 语言指针题目答对了。

`测试一下新模式，你可以干什么`——验证自定义模式是否生效。

### 性能对比：DSH vs ZCode

`同样的模型，同样的api接口，我在zcode上调用你的响应速度远远快于在dsh上的速度？这个是为什么`

排查发现是 dsh 的 system prompt 太长——注入了大量 AGENTS.md、技能目录、自进化记忆路径，token 消耗大。同样的模型，prompt 越长响应越慢。

这算一种"定制化税"：功能越多，系统提示越长，响应越慢。ZCode 快，因为它是白纸；DSH 慢，因为它脑子里装着我全部的历史。值不值？反正我选慢的。

### 磁盘清理：2.4GB 的罪魁祸首

`然后我看现在这个工作目录下储存占用特别大，我zcode比它小多了`

`我这边怎么显示总占用有2.4g多`

`这个我应该没有再用吧，我已经删除了这个插件：dsh-turn-rewind,这个是什么东西：@anthropic-ai/claude-agent-sdk 253MB`

`请你仔细去调查dsh里面这两个是干什么的：DSH的package.json里声明了claude.exe — Anthropic的Claude Code agent，codex.exe — OpenAI的Codex agent`

`这个真的安全吗？请你仔细检查：直接删node_modules重装`

`那你删除的意义是什么，反正都会装回来？`

`@anthropic-ai/claude-agent-sdk都引用在哪里？`

`我禁用了这个吗`

`那直接删除吧@anthropic-ai/claude-agent-sdk`

`开始吧`

2.4GB 的占用，追到最后是三个 SDK：`@anthropic-ai/sdk`、`@anthropic-ai/claude-agent-sdk`、`@openai/codex`。从 package.json 里全部移除。这些子代理功能在 Windows 上根本用不了（网络不通），占着 253MB+ 的空间。

从第一天偷偷装进来的那个包，到最后一天被我亲手删掉——`@anthropic-ai/claude-agent-sdk`，这三天它一直在。它丑，它大，它没用。从那天起，它和 codex 一起进了我的黑名单。

### 目录选择器 bug

`现在dsh怎么不能选择其他盘作为工作区域了？现在被限定在c盘（虽然现在目录在d，但这个是之前选择的，现在不行了`

`你看，现在页面是这样的，如果我把画箭头的地方改成d盘。它就下面的显示也变成d盘的了`

桌面应用的客户端代码里硬编码了 C 盘路径。改了一下，能选 D 盘了。`我重启了，没有变化`——又改了一版才搞定。

（改两版的原因：第一版改的是选择器的显示逻辑，第二版改的是实际路径的写入逻辑。前端最经典的"看起来修好了"。）

### 自进化记忆

整个三天里，每隔几个小时就做一次反思——`/cmchen-self-evolving-agent 开始反思`。对话记录里出现了 5 次。每次反思都把踩过的坑、学到的技巧写进记忆目录。

记忆目录里积累了 9 篇反思记录（2026-07-26 到 2026-08-18）、4 个进化技能（批量重构、转义安全写入、跨环境移植、中文路径问题）、一份用户画像。

## 收尾

三天。129 条对话。4.5MB 的会话记录。10 个提交。

最折腾的不是写功能——是让东西跑起来。装插件、改配置、修 bug、调代理、换搜索方案、清磁盘。桌面应用移植那五条"继续"，dsh-pocket 那四次白屏，搜索方案的三轮替换，玻璃主题在手机上的灾难——每一步都是真实的踩坑。

但每解决一个问题，这个工具就更像我自己的。视觉模型接到 Go 套餐不用额外花钱，dsh-pocket 让手机能接着电脑聊，学习模式让我可以拿它复习 C 语言数据结构，自进化记忆让它记住上次踩过的坑。

性能比 ZCode 慢？慢就慢吧。ZCode 是白纸，这张纸上有我三天的字。

反正代码不会自己跑，bug 不会自己好。而我明天肯定还会继续折腾。
