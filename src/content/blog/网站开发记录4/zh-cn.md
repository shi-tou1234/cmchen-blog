上一回写到 8 月 9 号，开源当天，我在结尾说：一个东西能不能从你的手里走到别人手里，才是另一回事。

25 天之后，git log 多了 57 次提交，总提交约 1191 次。这 25 天干了四件事：把博客装进了 exe、把安全补上了、把构建体积砍掉了 77%、还有移动端目录按钮的 6 次返工。

中间还顺带写了几篇文章。

事情是这样的。

* * *

08.10 到 08.12 那几天很平静。开源之后该收拾的已经收拾完了，我把 README 又翻新了一遍，从原来那几行字扩成了一份正经文档：项目概述、功能特性、技术栈、目录结构、安装指南、部署说明，全给补上了。然后参照 clay-blog 的实现，给主题切换加了圆形揭示动画——点击切换按钮后，新主题以按钮中心为圆心向外扩散，把整个页面盖过去再换色。不支持的浏览器降级为整体沉降动画。顺带把 `.pnpm-store/` 加进了 `.gitignore`。

开源之后的第一件事就是"让别人能看懂"。README 就是第一道门面。

* * *

08.14 号修了个很蠢的 bug。正文图片点击放大突然失效了，报错指向一行内联脚本。我盯着看了十分钟，没看出问题。GLM过来看了一眼：裸 import。

对，我在一段 `<script>` 里直接写了个 `import` 语句，没有包在任何模块声明里。JSX 直接报语法错误。这个 bug 本身就够丢人的了，更丢人的是我花了一个下午才找到原因。

* * *

08.17 号加了一个小功能：置顶博客卡片左上角的毛玻璃浮动标签。

就是那行金色的"· 置顶"胶囊，带一个呼吸动画的小圆点。代码只有 56 行，分布在 PostCard.astro 和 PostPage.astro 里。顺带尊重了 `prefers-reduced-motion`——系统开了减少动画的话，呼吸效果自动关掉。

* * *

08.18 号是这 25 天里提交最碎的一天，十几个 commit 挤在一天。

最显眼的是移动端交互大改造。汉堡菜单彻底换掉了，换成收拢式 FAB——平时就是一个带阅读进度环的加号按钮，点开才有菜单、目录、返回、评论、回顶。代码量 302 行，新建了一个 MobileFab.astro 组件，参考的是 Momo 主题的 FabMenu 交互。顶栏的汉堡按钮不再显示，只留在 DOM 里供 FAB 代理点击；768px 以下，文章页那堆旧的浮动按钮簇也整个藏掉了。侧边抽屉也精简了——删掉了和底部导航重复的「首页/归档/关于/工具栏」及提示语。

那天还顺手干了两件"对照 Momo 主题"的事。一件是新增 `++下划线++` 语法和脚注样式——remark-combined 插件增加了下划线分支，输出 `underline-text` 并支持嵌套。另一件是文学引用的渲染方式全部替换，从 Markdown 标准 `>` 语法改成 `:::quote` 自定义语法。表面上看只是改了个名字，实际上涉及所有引用块的渲染逻辑、样式覆盖、和主题系统的适配。三十多篇文章的引用格式，全部更新了一遍。

这件事让我想明白一个道理：自己写的自定义语法越多，维护成本就越高。每一次语法层面的改动，都意味着所有使用该语法的内容，都要跟着重新过一遍。

后台也在同一天扩容了。预览窗原来只能渲染 Markdown 标准语法，那天给它补上了全部自定义样式的渲染——`:::quote`、提示框、推导容器、音乐卡片、GitHub 卡片。客户端用 marked 渲染，服务端用 remark 插件，两边的输出要对齐，还得让 DOMPurify 的白名单放行对应的标签和类名。代码量 403 行，分布在 app.js 和 style.css 里。

然后工具栏也从原来那十几个按钮，扩展到了可以一键插入 8 种自定义样式：下划线、模糊、彩虹、拼音、脚注、引用卡片、音乐卡片、GitHub 卡片。脚注按钮最麻烦——要自动选取未占用的编号，然后在文末补全定义。

那天最后还干了一件不起眼但很实用的事：把后台所有设置栏目下的文字编辑区域都放大了。AboutPersonal、AboutTimeline、BlogGuide、HomeCover、ToolsLinks，六个页面，每个都多给了几行高度。

* * *

移动端目录按钮是另一个故事。

那天我给目录面板做了个 FAB 旁弹出的小窗口，加了延迟重试打开的逻辑。改了五版，每一版都觉得自己这次应该稳了。结果每一版都在某个设备上出问题——Safari 不认、安卓 WebView 不认、横屏不认。

五版，全部回滚。

08.18 那天的 commit message 长这样：一个 fix，五个 Revert，再一个 fix。先拆了五遍，再装一次。

最后的方案很简单：TOC 按钮始终可见，点击时延迟重试打开面板。简单粗暴，但管用。

人类在 UI 调试这件事上的效率，可能还不如一只偶然踩到键盘的猫。

* * *

08.19 号加了四件小事。RSS 订阅按钮、分享功能、社交卡片。评论和搜索加了加载提示——之前一直没做，总觉得不是重点，但其实没有加载提示的时候，用户会以为页面卡死了。搜索还加了懒加载，Pagefind 只在用户第一次搜索时才加载。封面图的缓存路径加了越界校验。

那天一共改了 11 个文件，新增 411 行。

* * *

08.23 号是这 25 天里最重的一天，17 次提交。

首先是桌面版打包上线了。

桌面版的想法来自一个很朴素的需求：有人想看我的博客，又懒得开浏览器。用 Electron 把它包成一个 exe，双击就能离线看全站，中文搜索也能用。

实现方案是 staging 精简打包：把博客构建产物和 Electron 主进程代码塞进一个临时目录，只装 serve-handler 这一个运行时依赖（12 个包的闭包），用 electron-builder 打包成 exe，最后自动清理所有中间产物，release 目录只留最终的可执行文件。成品 147MB。

一开始是纯离线的——安装包内置了完整的构建快照，本地启动一个 127.0.0.1 的静态服务托管。问题很明显：每次博客更新，用户就得重新下载一遍。后来改成了在线优先的策略——启动时先 HEAD 请求线上站点，能通则直接加载 GitHub Pages 的线上版本，新文章即时可见；连不上再回落到打包时的离线快照。还加了环境变量 `DESKTOP_ONLINE_URL` 覆盖，以后换自定义域名不用改代码。

离线快照的回落也不是无条件做的。出网请求只允许 http/https，拒绝环回地址、内网地址、保留地址。这多出来的几行校验，是后来补上的安全意识。

08.23 号还给桌面版加了自定义图标。那个文件不再是一张冷冰冰的默认 Electron 脸，有自己的图标了。

但桌面版代码还有几行改动没有提交——在线优先的加载逻辑和离线兜底之间，还有一些边界情况需要处理。

* * *

然后是全站安全加固。

以前总觉得安全是后端的事，一个静态博客能有什么安全问题。后来 AI 给我审代码，审出了一堆 P0 和 P1 漏洞，分了三档。P0 里最吓人的一个是：登录有个硬编码密码回退——安全配置加载失败的时候，自动落到一套写死的默认密码上。逻辑是"配置坏了你还能进去"，但代价是：谁拿到源码，谁就拿到了密码。

删了。加载失败就禁用登录，宁可进不去，不能裸奔。

那阵子补了一堆以前从来没听过的名词。登录态从明文改成密码派生凭据，登录失败加了限速锁定——连续输错五次锁定 15 分钟。GitHub API 端点加了 HTTPS 白名单和首次确认。密码哈希算法从 18 万迭代次数提到 60 万，据说是 OWASP 标准。同一个密码，以前要算 18 万次才能验证，现在要算 60 万次，暴力破解的成本翻了三倍多。

GitHub Token 的存储也改了。原来放在 localStorage 里，关不掉。后来挪到 sessionStorage——关标签页就清空。结果我用了两天就嫌烦，天天重新登录。又加了个「记住 Token」复选框，勾上就存永久。先为安全挪走，又为了方便加回来。安全与便利打架，打到最后 AI 给的方案是：都给你，你自己选。

那天的 commit message 里列了 6 个安全项编号（SEC-1 到 SEC-6），我自己现在也说不全每个编号对应什么具体改动。只记得那几个最吓人的。

* * *

WebP 批量压缩是最让我意外的收益。

原以为只是顺便优化一下图片，跑了个脚本，把 src/content 下超过 300KB 或宽度超过 1920px 的 PNG/JPG 全部转成 WebP（质量 85、最宽 1600px），删除原图，同步更新 Markdown 里的引用路径。源图少了 335MB，构建体积从 488MB 砍到了 111MB。

这件事让我重新理解了"性能优化"这个词。它不只是让你的网站跑得更快，而是直接影响你能不能把这个项目交到别人手里。488MB 的构建产物，别人克隆下来 `pnpm install` 再 `pnpm run build`，光 node_modules 和 dist 就要占一个多小时。111MB 的构建产物，快了一个数量级。

* * *

那天还做了一场大清理。

删了整套 Svelte。什么时候被我塞进项目的，我已经不记得了——大概是某个功能要用到，用完就一直躺着，集成、依赖、配置、页脚图标，全套。还有一堆写了没人用的死代码、失效的兜底函数、过时的文档。删完之后我发现，这个博客的代码第一次可以见人了。以前它就是一堆 AI 往上堆的东西，堆的时候没人想过以后会有人打开源码看。开源逼着我把家里收拾干净。

ESLint 也接上了 typescript-eslint，88 个 lint 错误清零。Astro 类型检查 356 个错误清零。这两样之前一直放着没管，那天一起清掉了。

旅行地图组件在那天被回退到了原始实现——之前改了之后地图加载不出来。整个"博客功能更新记录"目录被删了，留着没用。打包脚本也改了，每次打包完自动清理中间产物，release 目录只留最终的 exe。

那天一共改了 30 多个文件。

* * *

08.27 号给后台工具栏补了最后一类缺失的快速插入：5 类提示框（tip/note/important/warning/caution）+ 自定义标题提示框 + 任务列表。原来只有基础的 tip，现在全套都有了。写文章的时候点一下按钮，语法直接插到光标位置。

08.28 号更新了 about 页面的 timeline。08.29 号更新了 tools 页面的链接。08.30 号新写了一篇《如何给 AI 写提示词》，顺手修了 3 篇文章的提示框渲染 bug——之前是单行连写渲染失败，改成三行容器指令就好了。

* * *

现在呢，9 月 3 号，项目进入了一个相对平静的状态。桌面版能跑（虽然还有几行代码没提交），安全补上了，构建体积也降下来了。

但说真的，这种"平静"我越来越不信了。每次我觉得差不多该收尾了，过几天又会冒出来一个新功能。

开源之后我一直在想"做完"是什么意思。以前觉得，功能齐了、bug 少了、代码干净了，就叫做完。现在我觉得不是。做完是你不再想往里面加东西了。但我每天都还想加。

桌面版、开源版本、安全加固——这三件事说的是同一个方向：从"我自己能用"到"别人也能用"。博客从浏览器里走了出来，代码从私人仓库变成了别人的起点，安全从"以后再说"变成了"现在就得做"。

项目还在长，git log 还在加。
