## 一、默写的对象：一个最小顺序表

### 1.1 结构体 SeqList

顺序表 = 一段连续内存 + 两个记数变量。结构体定义：

```c
typedef struct {          // 只是声明了一个没有名字的结构体
    char *base;           // 门牌号：只存地址，格子按运行时需要现开，不写死大小
    unsigned len, size;   // 无符号：件数和容量不可能为负
} SeqList;
```

三个成员各司其职，用一句话记住分工：

> **`size` 是"买了几个格子"，`len` 是"现在真有几件货"。**
> 买了 10 个格子只放了 3 件，剩下 7 个是"有格没货"——那些格子里的内容是从没写过的内存（垃圾值）。

### 1.2 InitSeqList：初始化

```c
bool InitSeqList(SeqList *s1, unsigned size)  // 初始化
{
    s1->base = (char*)malloc(size * sizeof(char));  // 申请 size 个格子的内存
    if (!s1->base) return false;  // base 为空则报错
    s1->len = 0;                  // 长度清零
    s1->size = size;              // 确定最大长度
    return true;                  // 完成
}
```

要点：

1. `malloc` 的标准句式是**"(要几个) × (一个多大)"**：`size * sizeof(char)`；
2. `if (!s1->base)` 是"真检查"——`malloc` 失败返回 `NULL`，必须拦一下；
3. 初始化时 `len = 0`、`size = size`，一个表示"还没货"，一个表示"格子已就位"。

### 1.3 AppendItem：往表尾添加

```c
bool AppendItem(SeqList *s1, char item)  // 往表中末尾添加
{
    if (s1->len == s1->size) return false;  // 满表判断
    *(s1->base + s1->len++) = item;         // 写入并前进一格
    return true;
}
```

两个关键处：

**1. 满表判断用 `==`，不能写 `>`**。`len` 是一个个加上去的，用 `>` 永远追不上 `size`，判断形同虚设。

**2. `*(s1->base + s1->len++) = item` 一步做了三件事**：

- `s1->base + s1->len`：把地址往后移 `len` 格，指向第一个空位；
- `*()`：解引用，往这个格子里写入；
- `len++`：放完一个后计数前进一位。

### 1.4 GetItem：按位序取一个

```c
bool GetItem(SeqList *s1, unsigned pos, char *item)  // 按照位序取一个
{
    if (!pos || pos > s1->len) return false;  // 判断两个边界
    *item = *(s1->base + pos - 1);            // 取出来交给调用者
    return true;
}
```

这个函数是三默的"主战场"，因为它有**三零件**，缺一不可：

1. **出参** `char *item`：取到的字符靠它带出去，没有这个参数，函数体里的 `item` 就是未声明标识符；
2. **两个边界**：下界 `!pos` 挡住"没有第 0 件"（位序从 1 开始数），上界 `pos > s1->len` 挡住"取没货的格子"；
3. **赋值方向**：这是"取"——`*item = 格子里的值`（读出来给调用者）；写成 `*(base+pos-1) = item` 方向就反了，那是"放"。

> **注意**：线性表是从 1 开始数的，内存是从 0 开始数的，所以取第 `pos` 个对应 `base + pos - 1`，这里最容易错。

`pos` 用 `unsigned` 还有个妙处：万一有人传 `-1`，它会变成一个巨大的正数，被上界 `pos > s1->len` 一道挡掉，不会绕过去。

## 二、三次默写的全过程

### 2.1 三卷对照

| 卷 | 日期 | 状态 | 核心问题 |

| 二默 `02_练习.cpp` | 10-08 | 已批注修正 | 三个窟窿：函数又嵌套进 `main`、`GetItem` 三零件全丢、`malloc` 误写 `sizeof(size*)` |
| 三默 `03_练习2.c` | 10-09 | 已批注修正 | 三窟窿全清，只剩一处：`GetItem` 上界写成 `pos > s1->size` |

### 2.2 二默的九处批注

二默卷被批注改了九处，每处都是一个通用错误：

1. `stdbool` 拼错，少了 d，正确是 `stdbool.h`；
2. 三个函数定义全部移到 `main` 外面——**函数只能写在文件层，`main` 里只放调用**，嵌套定义 C/C++ 都直接报错；
3. 统一大小写：`typedef` 出来的是 `Seqlist`，函数签名里用的却是 `SeqList`——**C 语言大小写敏感**，小写的那个是"未定义类型"；
4. `malloc` 误写 `sizeof(size*)`：那是"一个指针的大小"（8 字节），不是要的 `size` 个格子；
5. 形参类型是 `char`（元素类型），不是 `unsigned`；
6. `GetItem` 补上出参 `char *item`——三零件之一；
7. 两个边界都写错：下界写成 `!s1->size`（跟下界无关），上界写成 `size`（应是 `len`）；
8. 赋值方向反了：写成了"放"而不是"取"；
9. `return 0` → `return false`，`bool` 函数里统一 `true`/`false`。

### 2.3 三默：同一个错又犯了一次

三默时函数骨架、出参、赋值方向全对了，但 `GetItem` 的上界又写成了 `s1->size`——**和二默同一个错**。批注里拿原版函数实际跑了一遍（容量 10，放了 A、B、C，`len = 3`）：

| 操作 | 原版（上界用 size）的结果 | 正确结果 |
| :--- | :--- | :--- |
| 取第 1 个 | 返回 `true`，读到 `'A'` | 合法 |
| 取第 3 个 | 返回 `true`，读到 `'C'` | 合法 |
| 取第 4 个 | 返回 `true`，读到**乱码** | 应该拒绝 |
| 取第 10 个 | 返回 `true`，读到**乱码** | 应该拒绝 |
| 取第 11 个 | 返回 `false`（碰巧被 `size` 挡住） | 应该拒绝 |

这个错很阴险：小规模测试时取到的都是刚放过的字符，看不出问题；真正读越界时才炸，而且炸出来的是随机内容——不一定崩，也可能悄悄给出错的答案。

### 2.4 从三默里看见的三件事

1. **函数骨架立住了**：结构体 + 三个函数签名，后两默连对两次；
2. **`GetItem` 的出参和赋值方向内化了**：三默一次写对；
3. **`len` 与 `size` 的分工还没分化**：同一个错犯了两次，是当前唯一的尾巴——变式测（元素类型 `char` 换 `int`、`pos` 换变量名）过了才算这道题毕业。

## 三、批注里沉淀的 C 语言课

### 3.1 malloc 的标准句式

```c
s1->base = (char*)malloc(size * sizeof(char));
```

记成口诀就是：**(char\*)malloc(要几个 × 一个多大)**。`sizeof(size*)` 这类笔误的根源是把"要几个"写进了 `sizeof`——转型写全的话，`sizeof` 什么一眼能看出来，笔误自己就现形。

### 3.2 函数只能定义在文件层

函数嵌套定义在 `main()` 里，C/C++ 都直接报错。正确的分工是：**函数在文件层定义，`main` 里只负责调用**：

```c
int main() {
    SeqList la;
    char ch;
    InitSeqList(&la, 10);   // 建表：容量 10
    AppendItem(&la, 'A');   // 放三件
    AppendItem(&la, 'B');
    AppendItem(&la, 'C');
    GetItem(&la, 2, &ch);   // 取第 2 个 → ch = 'B'（位序从 1 数）
    printf("%c\n", ch);
    return 0;
}
```

这个错连犯两次之后，第三默才真正长进骨架里。

### 3.3 大小写敏感

`Seqlist` 和 `SeqList` 是两个不同的标识符，`typedef` 什么名字，签名里就得用什么名字。命名统一是编译器替你守的纪律。

### 3.4 满表判断：`==` 而不是 `>`

`s1->len == s1->size` 已经是"满了"的唯一时刻。`len` 一步步加，用 `>` 判断永远为假——这也是"边界条件要成对想"的一个例子：写了上界，就要问下界在哪（`!pos`）。

## 四、C 与 C++ 的一线之隔

三默卷改成 `.c` 之后，批注特意指出一处 C/C++ 的分界线：

```c
s1->base = (char*)malloc(size * sizeof(char));  // (char*) 转型
```

1. **纯 C 里**：`malloc` 返回 `void*`，允许自动转成 `char*`，不写转型不算错（用 `gcc -std=c99 -Wall` 编译原版，零警告）；
2. **但建议写转型**，两个理由：
   - 这个文件哪天在 Dev-C++ 里"另存为 .cpp"，它就走 C++ 前端，`void*` 不能自动转，直接报错；
   - 转型是"我知道这堆字节要按 char 用"的自证，还能把 `sizeof(size*)` 那种笔误挡在门外。

还有一处对照：`malloc` 失败返回 `NULL`，所以 `if (!s1->base)` 走得到；而 C++ 的 `new` 失败是**抛异常**，根本到不了检查那一行——两套申请内存的哲学。

> **注意**：目前三份卷子的 `InitSeqList` 申请的内存都没 `free`。程序短、进程结束就回收，看不出问题；等后面写链表、每个节点单独申请时，漏了就是真泄漏。这是留给链表阶段的伏笔。

## 五、总结与注意事项

### 5.1 核心句式速查

| 句式 | 代码 | 说明 |
| :--- | :--- | :--- |
| malloc 句式 | `(char*)malloc(size * sizeof(char))` | 要几个 × 一个多大 |
| 真检查 | `if (!s1->base) return false;` | `malloc` 失败返回 `NULL` |
| 满表判断 | `if (s1->len == s1->size) return false;` | `==` 不能写 `>` |
| 尾插三步 | `*(s1->base + s1->len++) = item;` | 定位、写入、前进 |
| 取值边界 | `if (!pos \|\| pos > s1->len) return false;` | 下界挡第 0 件，上界挡没货 |
| 按位序取 | `*item = *(s1->base + pos - 1);` | 位序 1 起，内存 0 起 |

### 5.2 易错点提醒

1. **`len` 与 `size` 混用**（犯了两次的那个）：边界判断永远问一句"我挡的是**没货**还是**没格**"——上界是 `len`；
2. **`sizeof(size*)`**：把"要几个"误写进 `sizeof`，得到的是指针大小（8 字节）；
3. **取/放方向反**：`GetItem` 是 `*item = 值`（读出），写反就成了"放"；
4. **函数嵌套定义**：函数放文件层，`main` 只调用；
5. **大小写**：`Seqlist` ≠ `SeqList`；
6. **`bool` 函数**统一返回 `true`/`false`，不写 `return 0`。

### 5.3 默写要点

- **先默骨架再填肉**：结构体 + 三个函数签名先立住，再逐个填函数体；
- **出参意识**：函数要"带出"结果，形参就必须是指针（`char *item`），调用时传 `&ch`；
- **边界成对写**：写上界时顺手写下界，`!pos` 与 `pos > s1->len` 是一对；
- **拿测试说话**：对边界类错误，用小容量（放 3 件、容量 10）实测"取第 4 个、第 10 个"这种擦边操作，比肉眼检查有效得多。
